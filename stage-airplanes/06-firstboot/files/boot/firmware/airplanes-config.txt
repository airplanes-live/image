# airplanes.live feeder configuration.
#
# This file is applied on every boot. After a successful apply it is RENAMED
# to airplanes-config.applied.txt. If apply fails (typo, validation error,
# write failure, unknown key), the file stays in place AND a sibling
# airplanes-config.error.txt is written explaining what went wrong — fix the
# listed items, keep this file named airplanes-config.txt, then reboot.
#
# This file is bootstrap-only: a hostname so the feeder is reachable, WiFi
# credentials so it joins the network, and an optional backend pointer.
# Receiver location, MLAT display name, MLAT on/off, SDR gain, and 978 UAT
# toggling are all configured via the webconfig UI at
# http://<hostname>.local/ after first boot — that UI is the only place to
# change them.
#
# Format: KEY=value or KEY="value" (one per line, # for comments).
# Optional keys are commented out; uncomment and set the value to apply.
# Active lines must NOT carry inline comments — '#' only starts a comment at
# the start of a line.

# Override the network hostname so you can reach this Pi as <hostname>.local
# instead of raspberrypi.local. Useful if you run multiple Pis on the same
# network. Single-label only (no dots, no .local suffix — mDNS adds it
# automatically). 1-63 chars, letters/digits/hyphens, no leading or trailing
# hyphen.
#HOSTNAME=airplanes-feeder

# Optional WiFi setup for direct-flash users (dd / balenaEtcher / Win32 Disk
# Imager). If you used rpi-imager's "Edit Settings" (Wireless LAN tab) the
# credentials already landed elsewhere; leave WIFI_* commented out. Ethernet
# is always a fallback regardless of these values.
#
# WIFI_SSID  : 1-32 byte network name. Quote it if it has spaces.
# WIFI_PASS  : WPA-PSK passphrase (8-63 chars) or 64-hex pre-shared key. Omit
#              for an open network.
# WIFI_COUNTRY: ISO 3166-1 alpha-2 country code (e.g. DE, US, GB). Required
#              by regulators for the radio to transmit on certain channels.
#WIFI_SSID="My WiFi"
#WIFI_PASS="my-password"
#WIFI_COUNTRY=DE

# Point this feeder at a non-production backend (homelab, cloned airplanes.live
# setup) instead of feed.airplanes.live. Uncomment and set the hostname (or
# IPv4) of your backend. This sets both the mlat server and the readsb→aether
# beast forwarder in one line, using default ports (mlat 31090, beast 30004).
# Append :PORT to override the mlat port only (beast stays on 30004). For
# advanced topologies (bracketed IPv6, non-default beast port, multi-host
# fan-out), SSH in after first boot and edit /etc/airplanes/feed.env directly.
#FEED_HOST=feed.airplanes.test

# Point this feeder at a non-production website (homelab, staging) instead of
# https://airplanes.live for claim, diagnostics, and remote-config-sync POSTs.
# This is independent of FEED_HOST — FEED_HOST controls where ADS-B + MLAT
# traffic goes, WEBSITE_URL controls where the feeder talks to the website
# API. Full URL with scheme (http:// or https://), optional :PORT, optional
# /path. No userinfo, query, or fragment. For development only — production
# feeders should leave this commented out.
#WEBSITE_URL=http://airplanes.test/
